# Design: HOPLA 3.0 (phased: 2.2 → 3.x → 4.0)

Source review: `.agents/system-reviews/2026-10-01-revision-hopla-y-complementos.md` (local, gitignored).
Already shipped on `fix/hopla-quick-fixes`: tsc-check feedback (exit 2 + stderr), agent `tools:` field, SessionStart `resume|fork`.

## Problem

HOPLA (v2.1.1) has not changed since 2026-05-12 while Claude Code moved on:

- Commands and skills are unified upstream; `triggers:` is not part of the SKILL.md schema, and `hooks/prompt-route.js` (278 lines) duplicates native description matching and injects noisy hints (195 sessions, often off-target).
- No skill sets `model` / `effort`, so light tasks (orientation, reports, mechanical code) run on the most expensive model.
- `/hopla:archive` never produces canonical specs: across all local projects there are 92 plans with a `## Requirements Delta` and **0** `.agents/specs/canonical/` directories. Root causes:
  1. `commands/archive.md:31-35` only reads the delta from the brainstorm design spec and skips merging when there is none — the plan's own delta (`commands/plan-feature.md:191`) is never read.
  2. Plans are assumed to live in `.agents/plans/`; some projects (e.g. `phonetest-platform`) use `docs/plans/`.
- Overlaps with native features: `/code-review` (`--fix`, effort levels), `simplify`, `/init`, Workflows (replace `parallel-dispatch` / `subagent-execution`).
- 8 skills had zero uses in 120 days of the maintainer's sessions.

HOPLA is used by the maintainer, the HOPLA team, and the public, so nothing is removed without one release of deprecation notice.

## Chosen Approach

**B — phased delivery.** Urgent and non-breaking work ships first (2.2), structural changes ship with deprecation notices (3.x, see "Release split"), deprecated artifacts are removed last (4.0.0). Each release is its own PR with version bump in `package.json`, `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`.

Rejected: A (single huge PR delays the archive fix and is hard to review); C (removes things public users rely on without notice).

Out of scope for all three releases: MUST/SHALL normative format, bulk-archive, configurable workflow (OpenSpec gaps — revisit after canonical specs actually exist).

## Design

### 2.2 — fix what exists, no breaking changes

1. **Ship the quick fixes** already on `fix/hopla-quick-fixes`.
2. **Archive merges the plan's delta.**
   - Inputs: plan delta **and** design-spec delta. If both exist, merge them by requirement ID; on conflicting bodies for the same ID, show `⚠ conflict` in the summary and let the user pick.
   - Plan referencing the spec (`See spec: .agents/specs/<feature>.md`) → follow the reference, do not double-count.
   - Scenario check: for every ADDED/MODIFIED requirement without a `Given … When … Then …` scenario, **warn** in the summary (never reject).
   - Plans directory: read it from the project's `AGENTS.md` / `CLAUDE.md` (a declared plans path, e.g. `docs/plans/`), fall back to `.agents/plans/`. Archived plans go to `<plans-dir>/done/`.
   - `cli.js status` uses the same resolution so it lists plans in `docs/plans/` too.
3. **Router goes quiet.** `prompt-route.js` stops emitting hints (exits 0, no output). Phrases from `triggers:` move into each skill's `description` / `when_to_use` (≤ 1,536 chars combined). `triggers:` is removed from SKILL.md files. The hook entry stays in `hooks.json` (it becomes the 3.0 deprecation notifier).
4. **Frontmatter modernization** (see table below): `context: fork` + `model` only where the skill runs isolated; `when_to_use` everywhere; `disable-model-invocation` for `guide`, `create-prd`, `init-project`.
5. **session-prime minimal.** Inject only branch, git status summary, active plan, and compact-snapshot replay (~1 K chars). Drop the skills list (native skill listing already covers it). `/hopla:prime` remains the full on-demand orientation.
6. **env-protect false positive.** `hooks/env-protect.js` blocks Bash commands that only *mention* `.env` (e.g. `echo .env >> .gitignore`, `git add .env.example`, commit messages and comments that name the file, `--env-file .env` consumers, or a heredoc script whose text contains `.env` — this happened while writing this spec; measured in 2.1.1: `grep -r "\.env" src` and `rg "process.env" .` already passed and stay as regression rows). Block only commands that read the file contents (`cat`, `less`, `head`, `tail`, `source`, `.`, `grep <pattern> .env`, redirects from `.env`, etc.); keep `.env.example` / `.env.sample` allowed (also for file tools). Also protect `.dev.vars` (Cloudflare) against Read/Grep/Edit only — not in Bash, where it is read with `sed` to start the simulator without printing it.
7. **Positional arguments are 0-based.** In Claude Code `$0` is the first argument and `$1` the second. `system-review` currently receives plan and report swapped; `execute`, `review-plan`, `archive`, `code-review-fix` work only because Claude Code appends `ARGUMENTS:`. Switch the 5 commands to `arguments: [...]` + `$name`.
8. **Spike: native `/code-review` and the project checklist.** Verify whether native `/code-review` reads `.agents/guides/review-checklist.md` or honors checklist text passed as args. Record the result in this spec (Open Questions) — it decides the 3.0 code-review design.

### 3.0 — restructure with deprecation notices

1. **`commands/` → `skills/`**, same names (`/hopla:execute`, `/hopla:plan-feature`, …). Guides become nested skills keeping `/hopla:guides:<name>`. Update `CLAUDE.md` rule ("never the same name as command and skill") and README to the unified model.
2. **code-review = wrapper of native `/code-review`.** Load project checklist → run native review → if the spike showed the native review ignores the checklist, run a separate checklist pass afterwards → save report to `.agents/code-reviews/<slug>.md`.
3. **Workflows**, 3–6 agents, never for deploy / remote migrations / DNS / deletes:
   - `execute`: when a plan has ≥ 3 independent tasks, run them as a workflow (implement → verify per task), then the validation pyramid in the main session.
   - `code-review`: only via the native multi-agent review (no own workflow).
4. **Merge `migration` into `plan-feature`** (a "migration" plan type with phased rollout and rollback sections).
5. **`init-project` shorter**: delegate CLAUDE.md/AGENTS.md generation to native `/init`, keep only the `.agents/` scaffolding and HOPLA-specific sections.
6. **Deprecated (still installed, notice shown):** `parallel-dispatch`, `subagent-execution`, `refactoring`, `code-review-fix`, `agents/code-reviewer.md`, `agents/system-reviewer.md`, and `triggers:` support.
7. **Deprecation notifier** (repurposed `prompt-route.js` → `deprecation-notice.js`): on `UserPromptSubmit` (prompt starts with `/hopla:<deprecated>`) and `PreToolUse` matcher `Skill` (deprecated skill invoked), inject a one-line notice with the replacement. **Once per session per item**, keyed by `session_id` in a temp marker file.
8. `claude plugin validate` added to CI.
9. **High-risk guard, opt-in via `cli.js`** (`--setup-guard`, off by default): installs `high-risk-guard.js` to `~/.claude/hooks/` and registers it as a user-level PreToolUse(Bash) hook; `--uninstall` removes it. Not shipped as a plugin hook (plugin hooks are always on).

### Release split (decided 2026-10-02)

The 3.0 items above ship in several releases, each with its own plan, PR and version bump:

| Release | Items |
|---|---|
| **3.0.0** | 1 (`commands/` → `skills/`, same `/hopla:<name>`), 6 (deprecated items, still installed), 7 (deprecation notifier), 8 (`claude plugin validate` in CI) |
| 3.1.0 | 2 (code-review wrapper of native `/code-review` + separate checklist pass) |
| 3.2.0 | 3 (Workflows in `execute`) and **`effort:` frontmatter** (high for plan-feature, debug, rca), only after measuring that it keeps the prompt cache |
| 3.3.0 | 4 (`migration` → `plan-feature`), 5 (`init-project` via native `/init`) |
| 3.4.0 | **Statusline** (model, effort, ultracode, cache state if available), **global-rules.md** short section (Opus default, effort levels, Fable only on purpose and never in `-p`/background, ultracode off except audits/migrations/cross-cutting research, `/clear` between tasks, 1 h cache), **cli.js optional settings** (`workflowSizeGuideline: "medium"`, `workflowKeywordTriggerEnabled: false`, `CLAUDE_CODE_SUBAGENT_MODEL=sonnet` without `_FORCE`) next to 9 (`--setup-guard`) |

The order after 3.0.0 can change; each release is planned when the previous one ships. Details and sources for the bold items: `.agents/plans/backlog/hopla-3-0-notes.md` (folded here 2026-10-02).

**Removal ships as 4.0.0**, not 3.1: deleting public commands, skills and agents is a breaking change under SemVer. It still happens one release after the deprecation notices (at the earliest after 3.0.0).

### 4.0.0 — remove (was "3.1")

Delete everything deprecated in 3.0, add the removed names to the legacy cleanup lists in `cli.js`, delete `deprecation-notice.js` if nothing else is deprecated.

### Model per skill

`model` / `effort` are set **only on skills that run with `context: fork`**. Skills that work in the main conversation inherit the session model: switching models mid-session loses the prompt cache and can cost more than it saves.

| Skill | Mode | Model |
|---|---|---|
| `prime` | `context: fork` + `agent: hopla:codebase-researcher` + `background: false` | haiku |
| `hook-audit` | `context: fork` + `background: false` | sonnet |
| `system-review` | `context: fork` + `background: false` | sonnet |
| everything else (`archive`, `git`, `tdd`, `verify`, `worktree`, `review-plan`, `execution-report`, `brainstorm`, `plan-feature`, `execute`, `debug`, `rca`, …) | main conversation | inherit (no `model`) |

`execution-report` stays in the main conversation **without fork**: it needs the conversation to capture failures and deviations.

**Resolved (2026-10-01 research):** `AskUserQuestion` is removed from every subagent, so a forked skill cannot ask the user. `archive` asks at three points, so it stays in the main conversation without fork (maintainer decision; no helper skill). Forks run in the background by default since Claude Code 2.1.218, so every fork sets `background: false`. Plugin agents must be referenced with the plugin prefix (`agent: hopla:codebase-researcher`); a bare name silently falls back to the general-purpose agent.

`agents/codebase-researcher.md` is kept (model: haiku) as the fork agent for `prime`; the other two agents are deprecated.

## Requirements Delta

### ADDED Requirements
- REQ-ARCHIVE-001: Archive merges the plan's Requirements Delta
  - Scenario: plan-only feature — Given a completed plan with a `## Requirements Delta` and no design spec, When the user runs `/hopla:archive <plan>`, Then the delta's requirements are proposed for merge into `.agents/specs/canonical/<domain>.md`.
- REQ-ARCHIVE-002: Archive warns on missing scenarios
  - Scenario: requirement without scenario — Given an ADDED requirement with no Given/When/Then line, When archive builds the merge summary, Then it shows a warning for that ID and still allows approval.
- REQ-ARCHIVE-003: Archive honors the project's plans directory
  - Scenario: docs/plans project — Given an `AGENTS.md` that declares `docs/plans/` as the plans directory, When archive or `cli.js status` looks for plans, Then it lists and archives plans from `docs/plans/` into `docs/plans/done/`.
- REQ-DEPRECATION-001: Deprecated items notify once per session
  - Scenario: repeated use — Given a deprecated skill, When it is invoked twice in the same session, Then the deprecation notice is shown only the first time.

### MODIFIED Requirements
- REQ-ROUTING-001: Prompt routing hints (replaces previous version)
  - The UserPromptSubmit hook no longer injects skill hints; skill selection relies on native `description` / `when_to_use` matching.
- REQ-SESSION-001: Session priming (replaces previous version)
  - SessionStart injects only branch, git status summary, active plan, and compact snapshot; no skills list.

### REMOVED Requirements (4.0.0)
- REQ-SKILLS-TRIGGERS: `triggers:` frontmatter override (deprecated — not part of the Claude Code skill schema).
- REQ-SKILLS-PARALLEL: `parallel-dispatch` and `subagent-execution` (deprecated — replaced by Workflows).
- REQ-SKILLS-REFACTOR: `refactoring` (deprecated — covered by native `simplify`).
- REQ-REVIEW-FIX: `code-review-fix` (deprecated — covered by native `/code-review --fix`).

## Edge Cases & Risks

- **`model` on a non-forked skill** switches the model of the main session for that turn (prompt-cache cost, possible quality drop mid-conversation). Prefer `context: fork` for cheap tiers; verify exact semantics in the docs during 2.2.
- **Moving commands → skills** must keep `/hopla:<name>` and `$ARGUMENTS` working; plugin users without auto-update keep old copies until they refresh.
- **Archive merge** of plan + spec deltas for the same ID — conflict UI must be explicit; never silently pick one.
- **Plans-dir declaration** format must be documented in README and in `init-project`:
  ```markdown
  ## HOPLA
  - Plans: docs/plans/
  ```
  Missing or unparseable → `.agents/plans/`.
- **Deprecation marker files** in temp dir: must be per-session and tolerate missing `session_id`.
- **Removing hints** may make some skills fire less often until `when_to_use` is tuned — compare usage after a few weeks.

## Open Questions

- Spike result (2.2, 2026-10-01, Claude Code 2.1.287, `claude -p "/code-review <effort>"`, Sonnet, temp repo with an uncommitted exported `multiply()` without JSDoc next to a documented `add()`): **native `/code-review` does not read `.agents/guides/review-checklist.md`.** With the rule "HOPLA-RULE-7: every exported function must have a JSDoc block" only in the checklist, `high` flagged the missing JSDoc as a consistency gap with the neighbouring function and never cited the rule (it reported "no repo-level CLAUDE.md"). With the same rule in the repo `CLAUDE.md`, `high` cited HOPLA-RULE-7 verbatim as the finding. At `low` effort neither variant reported anything. Conclusion for 3.0: the code-review wrapper must run a separate checklist pass after the native review (or the checklist rules must live in CLAUDE.md), and should not use `low` when checklist rules matter.

## Ideas for 3.0 (research 2026-10-01 — copy the idea, do not install these plugins)

Do not install superpowers, mattpocock-skills or compound-engineering next to HOPLA: competing frameworks.

- code-review: 0-100 confidence score per finding, drop low-confidence ones (official code-review plugin).
- Receiving a review without performative agreement, and a guided branch finish (merge / PR / discard) — obra/superpowers `receiving-code-review`, `finishing-a-development-branch`.
- Capture learnings at the end of each task in execution-report / archive (compound-engineering).
- brainstorm: one question at a time before planning (grill-me, mattpocock).
- review-checklist lines inspired by pr-review-toolkit: "silent-failure-hunter" (swallowed errors in handlers), "type-design-analyzer".
- plan-feature: 2-3 parallel explorers with different angles (feature-dev) — fits the Workflows item.
- Turn repeated user corrections into hooks instead of text (hookify).
- `hopla:git`: optional cleanup of local branches whose remote is gone (`/clean_gone`), with approval.
- Pre-release review with plugin-dev's skill-reviewer and plugin-validator agents; tune descriptions with skill-creator's eval method (near-miss test queries).
- Official budget rules: descriptions share ~1% of the context (≤ 1,024 chars each, main use case first); measure with `claude plugin details hopla`, `/skill-doctor`, `/context`; only the first 5,000 tokens of an invoked skill survive compaction (critical rules on top); anything that must always hold goes in a hook.
